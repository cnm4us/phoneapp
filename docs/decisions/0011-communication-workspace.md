# 0011 Unified communication registry and Stage A workspace

Status: accepted for synthetic implementation, 2026-11-19 UTC. [Plan 0015](../plans/0015-unified-communication-workspace.md), Stage A. Later work/receipts/text/STT/AI stages remain separate.

Add migration 0007 with an append-only `communications` registry. A wrapper has its own UUID, stable source call/message ID, patient ID and exact source creation timestamp. Unique nullable source keys and an exactly-one-source check prevent duplicates; composite source/patient FKs prevent cross-patient wrappers. Existing source identifiers, call participants, durations, media state/files, device credentials and sessions remain untouched. Applied migration backfills existing records; new call/message creation registers in the same transaction. A reviewed additive reconcile command repairs imported missing wrappers idempotently, without rewriting source data or inventing receipts.

Classification/status are projected from live source rows rather than copied into mutable snapshots. Existing calls have an app-call category but no recorded actual audio/video usage, so actual format is Unknown; saved messages use their existing audio/video kind. Media endpoint origin was not persisted, so channel is Not recorded instead of inferring browser/native from a missing device ID. Original sender and logical addressee are distinct from care-team routing contact: staff-originated records target the stable patient; patient-originated media targets its recorded staff contact. Work/receipt state remains Not recorded until Stage B.

Both current patient relationship and source audience apply to every list/count/detail: calls require participation; unpublished drafts remain sender-only; published messages retain their existing care-team/patient audience. A wrapper or filter never grants new access. Patient payloads omit internal future clinical-note/discussion fields. Exact original upload is honestly Not retained for existing media, whose normalized playback remains available under its current short-lived grants. Source IDs, never registry IDs, address existing media APIs. No new transcription, AI, comments, live recording or billing credit is supplied by Stage A.

The provider overview can show all authorized patients; patient filters narrow the same list. Server-side kind/format/direction/channel/sender/logical-recipient/date filters apply before counts/pagination. Cursor is bound to actor and filters and sorted by immutable source time/wrapper ID; older-page refresh stays anchored to the same cursor. Views use America/Los_Angeles explicitly as the synthetic display-date default, with UTC persistence and tested DST day boundaries. This selects display/filter behavior, not a production billing timezone.

New `/api/communications/context`, `/list` and `/:id` opt-in contracts are advertised through account/message capabilities. The feature flag defaults off; old clients/API routes continue unchanged. The first workspace UI depends on the existing message feature; older native binaries missing media modules keep their call/history fallback. Active incoming/current/multi-device call notices remain outside archive filters. Native/browser compose/playback reuses the existing media owner and grant paths; account/patient/filter/detail changes clear stale data and stop active media. Filters are locked while an unsent draft/capture/transfer needs attention.

Rollout requires test upgrade/preservation/grants and private pre-migration backup, then project-only publication between calls. Current schema-compatible source can disable the workspace flag while retaining the registry, source history and old calling/media flows. Do not run a schema-blind pre-0007 binary or drop history to revert the UI. New bundled native previews and actual owner/device checks are recorded separately from browser/JS tests.
