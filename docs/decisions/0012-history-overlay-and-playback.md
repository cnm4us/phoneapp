# 0012 History overlays, quiet refresh and playback controls

Status: accepted for synthetic implementation, 2026-11-19 UTC. [Plan 0016](../plans/0016-communication-history-usability.md), following [registry ADR 0011](0011-communication-workspace.md).

Keep the registry, source IDs, source audiences, saved login and existing media transfer APIs unchanged. This slice is client presentation/state, with no migration, secret, storage or provider change. Native and browser use the same calendar and scrub-session models; no new dependency is required.

Native details and date picking use an in-app root overlay host above the retained idle list, with safe-area padding, independent scrolling and fixed Close/Reply actions. The root suppresses the host for settings, incoming prompts and live calls. This avoids a second native window/live-call video renderer; message audio ownership/interruption still belongs to the existing media controller. Browser uses accessible HTML dialogs, retained keyed row nodes, Escape/focus restoration and the same private media instance moved into the detail/composer slot.

Polling checks authorization and metadata at existing foreground intervals. State is published only for semantic changes; background checks do not toggle visible loading/disabled states. New matching entries are held while reading, paging or composing and revealed deliberately. Unchanged browser rows keep their DOM identity. Playback progress is local to controls, not history. Transient transport errors retain the last authorized presentation; confirmed access loss clears it and releases media. Native bridges preserve HTTP 403/404 codes for this distinction, while existing UNAUTHORIZED handling remains unchanged. Older binaries keep their existing bridge behavior until replaced.

Dates are civil YYYY-MM-DD values with explicit Pacific boundaries, not local-device timestamp conversions. Picker drafts have direct year/month/day selection, month/leap clamping and Cancel/Done/Clear; Apply dates commits the range. Existing server validation and inclusive end date remain authoritative.

Playback controls reuse existing pause/resume/seek/download adapters. Scrub sessions bound positions to known duration and restore the prior play/pause intent only if their generation is still current. Closing, source changes, background/calls and transfer cancellation invalidate pending seeks. Native video retains its fullscreen entry; installed Expo Video types document that native controls are enabled in fullscreen. Browser fullscreen includes the custom controls. Seeking creates no receipt or staff-time credit.

Patient/caregiver accounts hide patient selection for a single authorized record and use a bounded switcher for multiple explicit relationships; staff retain the overview. Reply records audio/video through the existing authorized recipient path, with deliberate recording/send and unsent-draft handling. An unavailable original staff recipient cannot silently fall back to another contact. Patient-originated video calls, distinct Audio Call, CC/Forward, stored response/workflow links, transcripts and summaries remain later work. Unsupported call/menu actions are disabled; source data and metadata retention remain intact when technical labels are hidden.

No data rollback is needed. Restore schema-compatible browser assets/native previews if necessary, preserving existing workspace feature recovery and source history. Actual phones must verify native layout/gesture/media/call behavior; browser and package checks do not establish it.
