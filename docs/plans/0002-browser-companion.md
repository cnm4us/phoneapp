# 0002 Browser companion for WebRTC testing

Status: implemented and deployed; manual native/Safari acceptance pending. Updated: 2026-11-16 (client date). Supporting plan for [M1](0001-webrtc-poc.md); implements a bounded first increment of COM-01 from [the PRD](../PRD.md).

## Outcome and scope

Serve a browser calling page at the existing HTTPS hostname so the owner can call the native iPhone app from Windows or Safari on an iPad. Reuse current invitation, signaling, and expiring TURN credentials without changing the native protocol or requiring a new iPhone build. Use synthetic conversations; no recording, patient data, persistence, or production patient portal.

## Current evidence

The native iPhone app is installed and its screen is visible per owner report. Android native build and server-side signaling/relay checks pass. The hostname currently serves a text status page; no browser client exists. The checkout has a running development service on `feat/webrtc-poc`, with draft PR 1. Preserve that runtime and extend the same branch. Keep M1 open pending real-device tests.

## Data and configuration

No DB/migrations or new secrets. The creator enters the existing private test key; it stays in memory. Second participants need only a room invitation. Optional browser invitation links use a fragment that is removed after reading; never send capability tokens in server URLs/logs. Build output is ignored and regenerated by a committed script. Host on existing EC2/nginx by established user instruction; no separate Sites hosting or account is needed.

## Risks and recovery

Safari media playback may need a tap; provide explicit playback recovery. Browsers may suspend background media, so keep this experiment foreground-only. Test service changes locally before restart, validate nginx before reload, and preserve the former config. Keep compiled assets available before restarting the service; roll back only this project's code/config if deployment fails.
