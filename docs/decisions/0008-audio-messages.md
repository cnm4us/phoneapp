# 0008 Patient-linked audio messages and private POC media

Status: accepted for synthetic development implementation, 2026-11-18. [Plan 0012](../plans/0012-audio-messages-shared-history.md).

## Context and decision

Patient history must exist before app enrollment and support both provider and patient messages. Keep messages independent from calls: migration 0005 adds `audio_messages` (metadata plus durable processing/asset state) and `message_media_grants`. Never fabricate a call or relax the existing call recording/transcript FKs. A sender/request UUID deduplicates creation; patient and recipient are immutable for that request. A successful input hash binds later retries to identical bytes. Sender attribution snapshots identify the account; they do not identify every physical speaker.

Access requires a current active account and patient assignment/binding. Published messages are shared patient communications. Pending/failed unpublished messages are sender-only. Existing calls in the combined feed retain participant-based access. Pre-enrollment messages become accessible after existing owner-issued verified enrollment binds the same patient record. Patient-facing feeds contain no internal notes or time-review records. Recipient staff identity supplies routing; shared triage queues are deferred.

Use a private project filesystem outside Git/web roots for this synthetic POC, behind the `Messages` storage boundary. Root mode 700, files 600, server-selected UUID keys, HTTPS authenticated upload/playback, no public nginx alias. Tests use a dedicated disposable temporary directory. This shares the EC2 failure domain and does not claim production archival/encryption readiness. Back up DB metadata and files together. A private object-storage implementation can replace the file operations later.

Native and browser clients request short-lived media grants through their existing authenticated JSON path. Grants are random, hashed in DB, bound to the current session, message and upload/play operation, and expire after two minutes. Upload is single-use; playback permits bounded Range/retry requests until expiry. Every use checks current session/device status and patient access. Send the grant in an Authorization header, never a URL. No long-lived bearer/refresh credential is needed by the recorder/player. This deliberately replaces the plan's proposed native binary-broker extension: existing serialized JSON refresh remains the sole credential owner, while file transfers operate outside its queue and cannot block Answer/End. Native media origin is fixed to the credential broker's server.

Pin Expo Audio 57.0.5, FileSystem 57.0.7 and its Expo Asset peer at compatible SDK 57 versions. Native transfer uses foreground upload/download tasks; browser uses authenticated fetch and private Blob URLs. Downloads go to app-private temporary files. Local drafts are not a durable offline queue and can be lost on app termination. Explicit Send precedes any upload. The first version refreshes the inbox while visible; no new background-message push is sent, and VoIP pushes remain exclusive to calls.

Normalize actual supported audio to mono AAC/M4A for playback. Parse/convert only local files with FFprobe/FFmpeg subprocesses, no shell/remote input, fixed format/protocol allowlists, low priority, CPU/address-space/file-size/time limits and one worker. Verify output duration, then rename before atomic DB publication. Lease-based jobs recover after restart; orphan/expired files are retried by cleanup. Synthetic defaults: 180 seconds, 10 MiB input, seven-day published audio, 24-hour pending expiry, 100 sends/user/day, 50 MiB accepted-input budget/user/day, 1 GiB global store, 1 GiB free-space floor, two simultaneous uploads. Available means persisted/accessible, not notified, read or listened. Media duration never becomes staff credit.

## Audio ownership and consequences

The pinned Expo module resumes recordings/players after some interruptions. Phoneapp applies the narrowly version/anchor-checked `scripts/patch-expo-audio.mjs` during postinstall to make message capture/playback require explicit restart. iOS native call notifications and an Android package-private receiver stop message audio when Phoneapp ringing/answer/outgoing control takes ownership, before relying on JS polling. JS also releases the recorder/player before media joins, on incoming-call observation, background and logout. This patch is app-specific; review/retest it on every module upgrade. It must be included in EAS archives and verified after clean install.

Both platforms need new native preview builds. Source inspection, browser audio or JS exports cannot prove real iPhone/Android microphone playback, CallKit/Telecom handoff, interruption behavior or seek quality. Keep those physical acceptance gates explicit. Decoder maintenance, disk/resource use, storage encryption/backup and retention remain bounded POC operation concerns; production design is separate. Disable the message feature to recover while retaining schema/history, and repair forward rather than dropping tables.
